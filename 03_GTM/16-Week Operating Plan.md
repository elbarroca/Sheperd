# 16-Week Operating Plan

## Corrections to the original proposal

- “Seven axes” actually lists eight.
- A two-year CRM architecture cannot be responsibly frozen in Week 2; build an MVP and version it after Weeks 6 and 12.
- “Fluent,” “expert,” “bulletproof,” “proven model,” and “lead-gen machine” overstate what a small 16-week sample can establish.
- Three to five closed deals by Week 12 is a stretch target without historical pipeline or cycle evidence.
- External work and customer-data access should not precede written engagement and data rules.

## Weekly execution

| Week | Work | Decision or output |
|---|---|---|
| 0 | Sign engagement; define authority, systems, confidentiality, IP, data rules, success definitions | Safe-start gate |
| 1 | Product walkthroughs; shadow calls; map journey; build glossary, claim register, baseline funnel | Source-of-truth map and gaps |
| 2 | ICP/personas v0; list audit; CRM MVP; talk tracks; discovery and data-request checklists | External-activation go/no-go |
| 3 | Clean first cohort; request warm introductions; send 10–15 reviewed touches | Cohort hypothesis 1 |
| 4 | Run discovery; capture roles, objections, pain, evidence availability, next steps | Message revision |
| 5 | Continue bounded outreach; begin partner interviews; coordinate secure data requests | Submission bottleneck review |
| 6 | Warm-sprint retrospective by cohort, not anecdote | Stop/continue/change decision |
| 7 | Sprint 1: one segment × persona × message × channel | Comparable cohort launched |
| 8 | Review replies, meetings, objections, stage movement; change one variable | Sprint 1 decision |
| 9 | Sprint 2 with next-best hypothesis; publish approved content only | Cohort 2 evidence |
| 10 | Review funnel and partner quality; improve data handoff | Bottleneck decision |
| 11 | Sprint 3; test strongest remaining entry point | Cohort 3 evidence |
| 12 | Review pipeline, valid submissions, proposals, losses, and cycle time | Scale, learn, or pivot gate |
| 13 | Consolidate playbook v1, stages, and persona/archetype evidence | Repeatability audit |
| 14 | Run one bottleneck experiment; implement measured website/CRM quick win | Before/after result |
| 15 | Define first-hire profile, onboarding, and capacity assumptions | Conditional scale plan |
| 16 | Present evidence, unresolved risks, resources, and next 90-day plan | Founder decision |

## Week 12 planning hypotheses — not targets

Original funnel math implies 50 attempts → 15–20 meetings → 3–5 submissions → 3–5 deals, including a 60–100% submission-to-close rate. Keep 3–5 deals as a stretch target only if existing warm pipeline and historical cycle data support it.

Illustrative base band for capacity discussion only:

- 3–5 qualified opportunities.
- 2–5 valid data submissions.
- 0–2 closed deals.
- Clear cohort evidence and loss/no-decision reasons.

Split warm introductions from cold outbound in every report.

Do not convert these bands into targets until the Week 2 baseline records list size, contactability, warm-introduction capacity, product/data review capacity, historic cycle evidence, and the signed engagement’s available hours. Record any adopted target as an internal decision with owner and date.

## Phase gates

### Week 2 — activation

- Written engagement complete.
- Approved claims and talk-track boundaries.
- CRM MVP and definitions operational.
- Secure data path and named reviewer established.

### Week 6 — warm sprint

- Comparable activity records.
- Objection and role patterns documented.
- Submission friction measured.
- One explicit stop/continue/change decision.

### Week 12 — repeatability

- Cohorts comparable by segment, persona, channel, and message version.
- Pipeline and cycle metrics trustworthy.
- Playbook supported by evidence, not only founder intuition.

### Week 16 — scale decision

- Bottleneck and capacity known.
- First hire and onboarding are conditional on evidence.
- Next 90-day investment has a measurable thesis.
